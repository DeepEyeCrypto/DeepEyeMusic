## Evidence labels

- `VERIFIED_IN_SOURCE`: behavior is directly present in cited source.
- `DOCUMENTED_BY_PROVIDER`: official, documented provider contract. Not established for private InnerTube behavior in this report.
- `VERIFIED_ON_DEVICE`: directly exercised on hardware. Not performed in Phase A.
- `INFERRED`: interpretation from code, not runtime proof.
- `NOT FOUND`: searched the pinned source and did not find the claimed mechanism.
- `PARTIAL`: interface/caller is traced, but implementation path or source unavailable.
- `UNAVAILABLE`: source could not be inspected.

## Important scope boundary

This is not a claim that SmartTube reproduces the official YouTube app’s recommendation algorithm. The pinned source contains private InnerTube request/response handling. `WatchNextResult` has separate explicit `nextVideoRenderer` and `autoplayVideoRenderer` accessors; the research has not yet completed the final consumer trace that proves which one SmartTube auto-plays in every queue/repeat/radio mode.
