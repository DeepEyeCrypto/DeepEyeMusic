# V4A DSP Debugging & Diagnostics Plan

## Goal
Implement a real-time diagnostic overlay and verbose telemetry mode for the V4A DSP Engine to surface active session IDs, effect states, gain budgets, and AudioRoute transitions.

## Current Context & Assumptions
- `DSPEngine.kt` manages standard Android `AudioEffect` classes alongside custom software processors.
- It exposes flows like `engineState`, `currentSessionId`, and `gainBudget`.
- I am assuming this task is to build a "Stats for Nerds" style debug tool for the DSP specifically, or to add deep logging for hunting session-detachment bugs. If there is a specific bug being hunted (e.g., AudioTrack route changes dropping the effect), this tool will make it visible.

## Proposed Architecture
1. Add a `verboseLogging` toggle to `DSPEngine` to selectively enable heavy telemetry (logging buffer sizes, re-attach events, and processor limits).
2. Expose a `DspDiagnostics` data class from `DSPViewModel` combining `EngineState`, `currentSessionId`, `currentPresetName`, and `GainBudget`.
3. Build a lightweight Jetpack Compose overlay (`DSPDebugOverlay.kt`) that can be optionally rendered in `SettingsScreen` or `CustomPlayerView`.

## Step-by-Step Implementation Tasks

### 1. Augment `DSPEngine` with Verbose Mode & Diagnostics
- **File**: `app/src/main/java/com/deepeye/musicpro/dsp/engine/DSPEngine.kt`
- **Action**: Add `var isVerboseLoggingEnabled = false` flag. Add a function `enableDebugMode(enabled: Boolean)`. Update the existing `attachSession`, `releaseSession`, and `reconnectAndRehydrate` methods to emit deep telemetry to Logcat when enabled.
- **Verification**: `adb logcat -s DSPEngine` while toggling the mode to see state transitions printed explicitly.

### 2. Create `DspDiagnostics` Data Model
- **File**: `app/src/main/java/com/deepeye/musicpro/dsp/model/DspDiagnostics.kt`
- **Code**:
```kotlin
package com.deepeye.musicpro.dsp.model

data class DspDiagnostics(
    val sessionId: Int = 0,
    val state: EngineState = EngineState.IDLE,
    val preset: String = "",
    val route: AudioRoute = AudioRoute.UNKNOWN,
    val gainBudget: GainBudget = GainBudget(0f, RiskLevel.SAFE)
)
```

### 3. Expose Diagnostics in `DSPViewModel`
- **File**: `app/src/main/java/com/deepeye/musicpro/dsp/engine/DSPViewModel.kt`
- **Action**: Add `val diagnostics = combine(...)` using the existing flows from `DSPEngine`.
- **Verification**: Compile and ensure no unresolved references. Command: `./gradlew compileDebugKotlin`

### 4. Build the `DSPDebugOverlay` UI Component
- **File**: `app/src/main/java/com/deepeye/musicpro/dsp/ui/DSPDebugOverlay.kt`
- **Action**: Create a simple dark-themed Compose card displaying the properties of `DspDiagnostics`. Add a switch/button to toggle `isVerboseLoggingEnabled` in the VM.
- **Verification**: Preview the composable or run on device.

### 5. Wire Overlay to `SettingsScreen` / `Audio Settings`
- **File**: `app/src/main/java/com/deepeye/musicpro/ui/settings/SettingsScreen.kt`
- **Action**: Add a "Developer: V4A DSP Stats" card at the bottom of the Settings screen that includes `DSPDebugOverlay`. 
- **Verification**: Run `./gradlew assembleDebug`, install on the Realme MT6835, navigate to settings, and confirm the debug panel dynamically updates when playing audio.

## Risks & Open Questions
- **Performance**: Polling DSP engine states and doing heavy string allocations in Compose can incur CPU overhead. The overlay should ideally throttle updates to ~2Hz.
- **Open Question**: Are we trying to debug a specific bug (like an AudioSession drop, latency issue, or crash)? If so, we should focus on writing a regression test for that specific bug rather than an overlay.
