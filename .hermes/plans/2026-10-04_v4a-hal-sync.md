# V4A-Core Forensics & HAL-Sync Protocol Implementation Plan

## Goal
Eradicate audio distortion, crackling, popping, and clipping on MediaTek MT6835 (Realme RMX3945) by explicitly disabling Audio Offload, multiplying AudioTrack internal PCM buffers by 4x, expanding ExoPlayer LoadControl buffers, and injecting FTZ/DAZ (Flush-To-Zero / Denormal-As-Zero) mathematical NaN traps across all ViPER DSP AudioProcessors.

---

## Current Context & Root Causes

1. **Audio Offload & HAL Corruptions**:
   - MediaTek MT6835 hardware audio offload attempts direct DSP hardware bypass, corrupting custom AudioProcessor PCM chains and resulting in stuttering and clipping.
2. **AudioTrack Buffer Underruns**:
   - ExoPlayer's default `DefaultAudioSink` allocates minimal AudioTrack PCM buffer sizes. When multiple software AudioProcessors (ViperBass, ViperClarity, TubeSimulator, FieldSurround) run in series, CPU scheduling jitter causes buffer underruns (crackling/popping).
3. **Subnormal / Denormal Float Slowdowns**:
   - During quiet passages or silence, IIR biquad filters in `ViperBassAudioProcessor`, `ViperClarityProcessor`, `TubeSimulatorProcessor`, and `CrossfeedProcessor` decay into IEEE 754 denormal floats ($< 10^{-15}$). ARM Cortex-A55 cores handle denormals via microcode traps that slow down DSP execution by up to 100x.
4. **NaN & Infinity State Poisoning**:
   - Nonlinear waveshaping and tanh saturation without strict bounds can generate NaN / Infinity values that persist in filter state registers, causing harsh digital clipping.

---

## Architecture & Proposed Approach

1. **ExoPlayer HAL & Sink Overhaul (`PlayerModule.kt`)**:
   - Set `DefaultRenderersFactory.EXTENSION_RENDERER_MODE_OFF` to force clean software PCM decoding.
   - Inject `DefaultAudioSink.AudioTrackBufferSizeProvider` with a 4x minimum PCM multiplier.
   - Enforce `setEnableFloatOutput(false)` (16-bit PCM) for universal MediaTek HAL stability.
   - Configure `DefaultLoadControl` with generous buffer durations (50s min, 100s max, 2500ms playback start).
2. **FTZ / DAZ & NaN Sanitization Across DSP Pipeline**:
   - Add inline `sanitize(Double)` and `sanitize(Float)` helpers in every DSP processor to flush subnormals ($|x| < 10^{-15}$) and trap NaN / Infinity.
   - Sanitize all filter feedback states (`x1`, `x2`, `y1`, `y2`, `lastCross`, `dc_y1`).
3. **Deterministic Processor Execution Order**:
   - Maintain strict psychoacoustic staging:
     `VocalRemoverProcessor` $\rightarrow$ `CrossfeedProcessor` $\rightarrow$ `FieldSurroundProcessor` $\rightarrow$ `ViperBassAudioProcessor` $\rightarrow$ `ViperClarityProcessor` $\rightarrow$ `TubeSimulatorProcessor` $\rightarrow$ `PlaybackGainProcessor` $\rightarrow$ `MasterLimiterProcessor` $\rightarrow$ `LufsAnalyzerProcessor`.

## Step-by-Step Implementation Tasks

### Task 1: Overhaul `PlayerModule.kt` for HAL-Safe AudioTrack Buffers & Zero Offload
- **File**: `app/src/main/java/com/deepeye/musicpro/di/PlayerModule.kt`
- **Actions**:
  1. Add `DefaultAudioSink.AudioTrackBufferSizeProvider` configured with:
     ```kotlin
     .setAudioTrackBufferSizeProvider(
         DefaultAudioSink.AudioTrackBufferSizeProvider.Builder()
             .setMinPcmBufferMultiplier(4)
             .setMaxPcmBufferMultiplier(8)
             .build()
     )
     ```
  2. Set `DefaultRenderersFactory.EXTENSION_RENDERER_MODE_OFF` to prevent hardware decoder / offload conflicts.
  3. Update `DefaultLoadControl` buffer parameters to:
     - `minBufferMs = 50000`
     - `maxBufferMs = 100000`
     - `bufferForPlaybackMs = 2500`

## Risks, Tradeoffs & Edge Cases

| Risk / Edge Case | Mitigation |
| :--- | :--- |
| **Increased AudioTrack Latency on Scrubbing** | `bufferForPlaybackMs = 2500` ensures instant playback start while AudioTrack's 4x buffer provides ~180ms hardware cushion, imperceptible for music playback and eliminating underruns. |
| **High Sample Rate Audio (96kHz/192kHz)** | `DefaultAudioSink` automatically scales buffer sizes by sample rate, and `AudioFormat.sampleRate` dynamically recalculates biquad filter coefficients. |
| **Float Conversion Overhead** | Inlining `sanitize` and using local primitive registers keeps DSP execution well under 2% CPU usage on ARM Cortex-A55 cores. |
